# 05 — macOS System Integration & OSS Competitive Landscape

*Research date: 2026-10-30. Scope: building a local, macOS-only, latency-first push-to-talk dictation + voice-command app (Wispr Flow alternative). OpenWhispr is covered in a separate doc and is only cross-referenced here.*

Method: I read the source of VoiceInk, Handy, FluidVoice, Hex (legacy Swift and new Rust), and OpenWhispr's Globe listener on `main` as of this date, plus their issue trackers, Apple docs and developer forums. **Code-derived facts are marked (src)**. Statements from vendor marketing or single-author blogs are flagged as such.

---

## TL;DR

1. **Hotkey:** use **one active `CGEventTap`** (`.cgSessionEventTap`, `.headInsertEventTap`, `.defaultTap`) on a **dedicated high-QoS thread**, listening to `keyDown | keyUp | flagsChanged` (plus mouse events if you support mouse buttons). Modifier-only keys (Fn = keycode 63, Right ⌥ = 61, Right ⌘ = 54) arrive as `kCGEventFlagsChanged`. Under **Secure Input**, taps stop getting `keyDown/keyUp` but **`flagsChanged` still flows**. So a modifier-only push-to-talk key (Fn / Right ⌥) keeps working in password fields and in terminals with Secure Keyboard Entry on. Fall back to Carbon `RegisterEventHotKey` for keyed shortcuts (Handy does this) (src).
2. **Globe key:** you **cannot** consume the Globe key's system action (emoji picker, input-source switch, Dictation) from an event tap. WindowServer runs it ahead of taps. The fix is to set `AppleFnUsageType` to "Do Nothing" while your app owns the key, using the private `TISUpdateFnUsageType` from Carbon (which applies live), and to restore it on exit. OpenWhispr does exactly this (src).
3. **Insertion:** default to **clipboard + synthesized ⌘V** (CGEvent, `.cghidEventTap`, private event source). Mark the pasteboard with `org.nspasteboard.TransientType` / `ConcealedType` / `AutoGeneratedType`, and restore it after a guarded delay of 250–500 ms. Add **AX `Edit > Paste` menu press** and **AX `kAXSelectedTextAttribute` set** as fallbacks, plus **Unicode typing** (`CGEventKeyboardSetUnicodeString`, ≤20 UTF-16 units per event) for remote desktops and paste-hostile fields. Handy's **promise-pasteboard "read receipt"** (src) is the most robust restore-timing technique seen anywhere.
4. **Audio:** to avoid the orange privacy dot while staying fast, **prepare/initialize the AUHAL/AVAudioEngine without starting it**, then start on key-down (VoiceInk does this) (src). Prefer the built-in mic when the default input is Bluetooth: an AirPods mic forces HFP (16 kHz mono), degrades playback and adds 0.3–1.5 s route-switch latency. Resample to 16 kHz mono Float32. Use Silero VAD for trimming, not for endpointing in push-to-talk.
5. **Distribution:** Developer ID + Hardened Runtime + notarization, **no App Sandbox** (CGEvent posting and cross-app AX are effectively incompatible with MAS review; Guideline 2.4.5 rejections are documented). Sign every build, including dev builds, with a **stable identity**. An ad-hoc cdhash identity resets TCC on each rebuild.
6. **Stack:** native **Swift/AppKit (+SwiftUI for settings)** wins for a macOS-only, latency-first tool. All the key APIs are first-class, idle RAM is about 30–80 MB versus 150–500 MB for Electron, and you get CoreML/ANE models through FluidAudio and WhisperKit. Tauri/Rust is viable (Handy, new Hex) but every macOS API goes through `objc2` FFI.
7. **Fork base:** **FluidVoice** (GPL-3, Swift, 12.6k★) is the closest to Wispr Flow: Command Mode, Write Mode, context capture, fastest Parakeet. **VoiceInk** (GPL-3, Swift, 7k★) has the most battle-hardened paste and hotkey code but doesn't accept PRs. If you need **MIT**, start from **legacy Hex** (Swift/TCA, archived, MIT) or **OpenSuperWhisper** (Swift, MIT), and borrow ideas (not code) from the GPL apps. **Handy** (MIT, 35k★) is the best-architected cross-platform reference, but it's Tauri.

# Part 1 — macOS integration layer

## 1.1 Global hotkey on a single key (including modifier-only keys)

### API options compared

| API | Can see modifier-only keys (Fn, R⌥, R⌘)? | Can swallow the event? | Works under Secure Input? | Permission | Notes |
|---|---|---|---|---|---|
| **`CGEvent.tapCreate` `.listenOnly`** | Yes, via `kCGEventFlagsChanged` with the keycode in `kCGKeyboardEventKeycode` | No | `flagsChanged` yes; `keyDown/Up` **no** | **Input Monitoring** (`CGPreflightListenEventAccess` / `CGRequestListenEventAccess`) | Lowest privilege. Can't stop the key from reaching the app (for example, R⌥ still composes characters). |
| **`CGEvent.tapCreate` `.defaultTap` (active)** | Yes | Yes (return `nil`) | Same as above | **Accessibility** (also implies listen access) | Used by VoiceInk, Hex, OpenWhispr, and Wispr Flow's Swift helper (per a teardown). It must answer fast: a slow callback gets `tapDisabledByTimeout`, and you must re-enable it. |
| **`NSEvent.addGlobalMonitorForEvents(.flagsChanged/.keyDown)`** | Yes (`.function` flag for Fn) | No | No keyDown | Accessibility/Input Monitoring | Main-thread delivery. Simpler, but it can't suppress events and is subject to main-thread jank. OpenWhispr uses it for Globe. |
| **Carbon `RegisterEventHotKey`** | **No** (needs a non-modifier key; Fn is not representable) | Yes (it consumes the combo) | **Yes**, unaffected by Secure Input | None | Used by `sindresorhus/KeyboardShortcuts` and `tauri-plugin-global-shortcut`. Can't do key-up for push-to-talk reliably for all combos, and has no single modifier keys. |
| **IOHIDManager** (`kIOHIDOptionsTypeNone`, keyboard usage page) | Yes, raw HID usages (including Fn on Apple keyboards, usage page 0xFF / 0x03) | No | Yes, reads raw HID | **Input Monitoring** (`IOHIDRequestAccess(kIOHIDRequestTypeListenEvent)`) | Device-level, so it bypasses Secure Input for observation. Needs per-device matching, and only Apple keyboards emit Fn. A useful *secondary* signal. |

Key facts and citations:

- **Fn/Globe** is virtual keycode **63** (`kVK_Function`), and appears as `CGEventFlags.maskSecondaryFn` on `flagsChanged`. [keytap keycodes](https://docs.rs/crate/keytap/0.3.0/source/src/platform/macos/keycodes.rs). Right ⌘ = 54 (`kVK_RightCommand`), Right ⌥ = 61, Right ⇧ = 60, Right ⌃ = 62. To tell left from right, check the keycode on the `flagsChanged` event, not the flags. The flags are side-agnostic except through the device-dependent `NX_DEVICERCMDKEYMASK` bits.
- **Fn only exists on Apple keyboards.** Third-party keyboards don't emit the Fn flag (Handy README "fn and Globe Key Shortcuts"). Karabiner can remap. Synthesized Fn from userland is ignored by the system ([Apple forum 766200](https://developer.apple.com/forums/thread/766200)).
- **Tap → permission mapping:** `.listenOnly` triggers Input Monitoring and `.defaultTap` triggers Accessibility; Accessibility implies listen access ([Apple forums 122492](https://developer.apple.com/forums/thread/122492), [828052](https://developer.apple.com/forums/thread/828052)). `IOHIDCheckAccess` is known to report stale denials. Hex treats "events are flowing" as ground truth over `IOHIDCheckAccess` (src: `kitlangton/Hex/Hex/Clients/KeyEventMonitorClient.swift`, issue #250). New Hex says it "does not need Input Monitoring" because it uses an Accessibility-backed active tap.
- **Tap robustness pattern (VoiceInk, src):** `ShortcutEventTapThread` runs a dedicated `Thread` with `qualityOfService = .userInteractive`, its own `CFRunLoop` kept alive by an `NSMachPort`, and tap callbacks that never wait on main. It handles `tapDisabledByTimeout/ByUserInput` by re-enabling, and a 10 s recovery timer re-installs dead taps. Files: `VoiceInk/Features/Shortcuts/Coordination/ShortcutEventTap*.swift`, `ShortcutMonitor.swift`.

### Suppressing the Globe key's system action

- The Globe action (`AppleFnUsageType` in `com.apple.HIToolbox`) is fired by WindowServer **before** event taps, so returning `nil` from your tap does **not** stop the emoji picker or input-source switch. OpenWhispr's `resources/macos-globe-listener.swift` (src) says so explicitly and solves it as follows:
  - It `dlsym`s **`TISGetFnUsageType` / `TISUpdateFnUsageType`** from Carbon. That's what System Settings calls, and it applies **live**. Writing the default with `defaults write` only applies after the next login.
  - It sets the value to **0 = Do Nothing** while the app owns the key. It records the original value plus whether the key existed in a crash-recovery marker file, and restores on exit only if the value is still the one it set. If the user changed it meanwhile, the user's choice wins.
  - Value mapping: the OpenWhispr code uses 0 = Do Nothing. Third-party docs disagree on the enum ordering ([macos-defaults](https://macos-defaults.netlify.app/keyboard/applefnusagetype.html), [nix-darwin](https://mynixos.com/nix-darwin/option/system.defaults.hitoolbox.AppleFnUsageType)), so **read `TISGetFnUsageType()` at runtime** rather than hard-coding.
- Also make sure macOS Dictation's shortcut ("Press 🌐 twice" / "Press Control twice") isn't bound to the same key. Guide the user to System Settings › Keyboard › Dictation › Shortcut, or detect it.
- Background on Fn: [Michael Tsai, "The Hidden Secrets of the Fn Key"](https://mjtsai.com/blog/2023/11/20/the-hidden-secrets-of-the-fn-key/). Keyboard Maestro also can't use Fn as a hotkey through public APIs ([KM forum](https://forum.keyboardmaestro.com/t/wish-list-add-fn-globe-as-a-modifier-to-use-as-hotkey-or-usb-key-trigger-is-there-a-workaround-in-the-meantime/36500)).
- **Fn chords:** don't swallow Fn+Delete, Fn+arrows or Fn+F-keys. Handy's PR #1767 moved from a blocking manager to observe-only matching for bare Fn: Fn-down starts, a keyboard key joining the chord cancels dictation **and passes through**, and mouse input does not cancel ([Handy #1767](https://github.com/cjpais/Handy/pull/1767)).

### Hold-to-talk, double-tap-to-latch: thresholds used in the wild (src)

| Project | Modes | Thresholds |
|---|---|---|
| **Hex (legacy Swift, `HexCore/Logic/HotKeyProcessor.swift`)** | press-and-hold + double-tap lock, combined in one state machine | double-tap window **0.3 s**; `minimumKeyTime` **0.15 s** (raised to **0.3 s** for modifier-only hotkeys, to avoid conflicts with OS shortcuts); another key pressed **within 1 s** of start → cancel as accidental (`pressAndHoldCancelThreshold`), and after that extra keys are ignored; a mouse click within 0.3 s on a modifier-only hotkey → silent discard (Option-click conflicts); ESC always cancels; "dirty state" ignores all input until full release, so the user can't "backslide" into the hotkey |
| **VoiceInk (`RecordingShortcutManager.swift`)** | toggle / pushToTalk / **hybrid** / doubleTap | hybrid: press **≥0.5 s** = push-to-talk (stop on release), shorter = hands-free latch; doubleTap: each tap ≤ **0.7 s** and inter-release ≤ **0.7 s**; interruption window **1.0 s** (`ShortcutMonitor.shortcutInterruptionWindow`) |
| **Handy** | hold / toggle / both (`ShortcutActivation`); double-tap in PR #1547 | — |
| **FluidVoice** | `HotkeyActivationMode`; "Hold Space to Mute" during hands-free | — |

Recommended design:
- One state machine: `idle → pressing → holding(ptt) | tapped → latched`.
- Start capture **immediately on key-down**. Don't wait for the hold threshold, or you lose the first syllable. If the press turns out shorter than ~150–300 ms and no second tap follows within ~300–350 ms, discard the audio silently.
- If a non-modifier key is pressed while a modifier-only hotkey is held within ~300 ms–1 s, cancel: the user is typing a shortcut like ⌥←.
- Wait until all hotkey modifiers are **physically released** before posting ⌘V. Otherwise held modifiers merge into the synthesized chord: Handy #2051 has Ctrl+Alt+V instead of Ctrl+V, and VoiceInk #1000 finds that a still-held stop key corrupts the paste ([Handy #2051](https://github.com/cjpais/Handy/issues/2051), [VoiceInk #1000](https://github.com/Beingpax/VoiceInk/issues/1000)).

### Secure Input

- Password fields, Terminal/iTerm2 "Secure Keyboard Entry", and some apps that leak it (for example Cursor, [forum report](https://forum.cursor.com/t/cursor-leaks-secure-event-input-breaks-all-system-wide-input-taps-until-quit-or-screen-lock/167585)) enable `EnableSecureEventInput`. Apple guidance: [TN2150 Using Secure Event Input Fairly](https://developer.apple.com/library/mac/technotes/tn2150/_index.html).
- **Precise behavior (Handy `src-tauri/src/secure_input.rs`, src):** "CGEventTaps stop receiving KeyDown/KeyUp events while FlagsChanged still flows." Handy then:
  - polls `IsSecureEventInputEnabled()`;
  - finds the culprit process on a best-effort basis (the IORegistry `kCGSSessionSecureInputPID` is often wrong, [radar 48953777](https://openradar.appspot.com/48953777));
  - when secure input is *sustained*, **shadow-registers keyed bindings through Carbon** (unaffected), and shadows Escape/cancel while recording;
  - surfaces the situation to the user. [Hammerspoon eventtap docs](https://hammerspoon.org/docs/hs.eventtap) confirm taps lose key events.
- Implication: **default to a modifier-only key (Fn or Right ⌥)**. It keeps working under Secure Input. Synthesized ⌘V still *posts* under secure input (secure input blocks reading, not posting). Pasting into a real password field is undesirable anyway, so detect `kAXSecureTextFieldSubrole` and refuse.

## 1.2 Audio capture

| Option | Pros | Cons |
|---|---|---|
| **AVAudioEngine** `inputNode.installTap` | Simple; easy format conversion with `AVAudioConverter`; `setVoiceProcessingEnabled(true)` gives AEC/AGC | Always follows the *system default* input unless you set `kAudioOutputUnitProperty_CurrentDevice` on the underlying AU; configuration-change notifications on route switches; [Marco Arment-style complaints about AirPods](https://supermegaultragroovy.com/2021/01/26/it-s-over-avaudioengine/) ([follow-up](https://supermegaultragroovy.com/2021/01/28/more-on-avaudioengine-airpods/)) |
| **AUHAL (`kAudioUnitSubType_HALOutput`) directly** | Picks a device **without changing the system default**; can be *initialized but not started*; lowest latency | More code; must handle sample-rate changes (VoiceInk #956: stale AUHAL after a device format change → empty recordings) |
| **AVCaptureSession** | Device selection; fine for files | Higher latency, more overhead; not ideal for PTT |

- **Warm vs privacy indicator:** the orange mic dot appears only while I/O is *running*. VoiceInk's `CoreAudioRecorder` (src) "prepares AUHAL for the selected device without starting capture" and reuses the setup across recordings: `AudioUnitInitialize` early, `AudioOutputUnitStart` on key-down. That gets a cold-start-free first buffer without a permanent indicator. FluidVoice similarly has `AudioCaptureIdlePolicy` / `AudioStartupGate` / "idle prewarm" logic, with Bluetooth-specific deferred route recovery (src). Optionally keep a ~200–300 ms ring buffer running only *while the hotkey is held* to absorb device start jitter.
- **Bluetooth / AirPods:** opening the AirPods mic forces **HFP** (mono, 16 kHz mSBC or 8 kHz CVSD). Playback quality degrades for everything, media apps may pause on the route change, and the switch takes noticeable time ([JUCE forum](https://forum.juce.com/t/fr-disable-bluetooth-hfp-by-default/49875), [AirPods 16 kHz SO](https://kiwix.lema.org/stackoverflow.com_en_all_2023-11/questions/63760975/record-audio-from-airpod-pros-at-higher-sample-rate-than-16khz)). Mitigations seen in the wild:
  - Handy PR #1146: **prefer a non-Bluetooth input when the default is Bluetooth** ([link](https://github.com/cjpais/Handy/pull/1146)).
  - Handy #2154: wait until real (non-zero) samples arrive before marking a Bluetooth mic "ready".
  - Handy #1991: silent AirPods recordings when the iPhone also plays audio.
  - VoiceInk #567: skip the built-in mic in clamshell mode.
  - Recommendation: default to "built-in mic unless the user explicitly chooses a headset", and show the active device in the HUD.
- **16 kHz:** capture at the native rate (usually 48 kHz) and convert with `AVAudioConverter` (or `rubato` in Rust, as in Handy) to **16 kHz mono Float32**, which is what Whisper and Parakeet expect. Do it in the tap callback, chunked, so audio is ready the instant the key is released.
- **VAD:**
  - **Silero VAD** (ONNX, ~2 MB, <1 ms per 30 ms chunk on CPU) is the de facto standard. Handy uses it plus `earshot` and a smoothing layer (`src-tauri/src/audio_toolkit/vad/`). FluidAudio ships a CoreML Silero.
  - **WebRTC VAD** is lighter but noisier.
  - In push-to-talk, use VAD for **trimming leading/trailing silence and rejecting empty presses** (prevents Whisper "Thank you." hallucinations), not for endpointing. For hands-free latch mode, VAD with ~600–1000 ms hangover can auto-stop.

## 1.3 Text insertion

### Techniques

1. **Clipboard + synthesized ⌘V (the default everywhere).** VoiceInk `CursorPaster.swift` (src):
   - `CGEventSource(stateID: .privateState)`, keycodes 0x37 (⌘) and 0x09 (V) with `.maskCommand`, posted to `.cghidEventTap` with 10 ms gaps.
   - **200 ms pre-paste delay** lets focus settle after the HUD/hotkey.
   - Restore delay is at least **250 ms**, user-configurable up to 5 s. The restore is guarded by checking that the pasteboard still holds *our* text **and** a private `com.VoiceInk.PasteSession` UUID type.
   - **Keyboard-layout gotcha:** on "… – QWERTY ⌘" layouts (Dvorak-QWERTY ⌘), the AppleScript `keystroke "v"` resolves wrongly. VoiceInk uses `key code 9` instead. The CGEvent path uses virtual keycode 9, which is physical V. That's correct for most layouts, but non-QWERTY layouts can still break (VoiceInk PR #652).
   - Known bug pattern: **back-to-back dictations lose the user's clipboard** when the second snapshot captures the first transcript. Fix: skip snapshots that carry your own session marker ([VoiceInk #1024](https://github.com/Beingpax/VoiceInk/issues/1024)).
2. **Pasteboard hygiene (nspasteboard.org conventions):** VoiceInk `ClipboardManager.swift` sets `org.nspasteboard.source` (bundle ID), `org.nspasteboard.TransientType` and `org.nspasteboard.AutoGeneratedType`. Handy adds **`org.nspasteboard.ConcealedType`**, so clipboard managers (Maccy, Paste, Raycast) skip the transcript. These are conventions; nothing enforces them ([nspasteboard.org](http://nspasteboard.org)).
3. **Promise pasteboard with read receipt (Handy `src-tauri/src/paste_tx/macos.rs`, src).** The best restore-timing technique found:
   - Declare the type with `declareTypes:owner:` instead of writing data.
   - When the target app actually reads, AppKit calls `pasteboard:provideDataForType:` on your owner object. That callback is a "read receipt".
   - Restore the old clipboard once receipts go quiet, guarded by `changeCount`.
   - Result: no guessed delay, and confirmation that the paste was consumed. A `paste_not_landed` signal becomes possible (FluidVoice has a `TextDeliveryFailure.pasteNotLanded`).
4. **AX menu press: `Edit > Paste` via `AXPress`.** Hex legacy tries cmdV → menuItem → AX in sequence (src: `PasteboardClient.swift`, via AppleScript System Events menu). VoiceInk #1000 reports that in **Chromium browsers (Brave, Chrome, Arc)**, synthetic ⌘V into web-page fields **fails intermittently after the first paste** while a physical ⌘V works. `AXPress` on the Edit›Paste menu item (Cmd-char "V") **landed every time**. Use that as the primary path for Chromium-family bundle IDs.
5. **AX direct set: `AXUIElementSetAttributeValue(focused, kAXSelectedTextAttribute, text)`.** Replaces the selection, or inserts at the caret, without touching the clipboard. Works well in **native Cocoa** text views (Notes, TextEdit, Mail, Xcode, Messages) and many SwiftUI fields. It is unreliable or no-op in **Electron/Chromium** (the element often reports success but the web content ignores it, or the AX tree isn't exposed), in **terminals**, in **Google Docs** (canvas rendering), and in **Java/JetBrains** (Java Access Bridge AX is partial). Avoid `kAXValueAttribute` set: it replaces the whole field and kills undo.
6. **Unicode typing via `CGEventKeyboardSetUnicodeString`.** VoiceInk `DirectTextTyper.swift` (src):
   - Chunks of **≤20 UTF-16 units** per event (some receivers truncate longer payloads), with **10 ms** between chunks. Surrogate pairs are never split.
   - LF/Tab are sent as separate events, with LF mapped to Unicode CR plus Shift so rich editors get a line break, not "send".
   - Control characters are rejected.
   - Use for **remote desktop / VNC / Screen Sharing**, games, and fields that block paste. It's slow for long text (~1–2 s per 1 kB) and doesn't touch the clipboard.

| Remote desktop / Screen Sharing / VMs | ❌ (pastes the local clipboard only if clipboard sync is on) | ❌ | ❌ | ✅ (VoiceInk "Remote Desktop Typing") | VoiceInk #928: stale target window in Screen Sharing |

Recommended insertion pipeline (per bundle-ID policy table, user-overridable):
1. Read `NSWorkspace.frontmostApplication` (bundle ID, pid) at **key-down** and again before paste. Abort or redirect if focus changed, or if `kAXFocusedUIElementAttribute` has `kAXSecureTextFieldSubrole`.
2. Wait until hotkey modifiers are physically up (`CGEventSource.flagsState(.hidSystemState)`).
3. Native Cocoa: AX `selectedText` set, falling back to ⌘V. Chromium/Electron: AX Edit›Paste, then ⌘V. Terminals: ⌘V only, with no trailing newline. Remote: Unicode typing.
4. Use a promise pasteboard (Handy pattern) with the transient/concealed markers. Restore on receipt or after a 500 ms timeout, guarded by `changeCount` plus a session-ID type.
5. Verify (optional): re-read AX `kAXValueAttribute`/`kAXNumberOfCharactersAttribute` delta, or the pasteboard read receipt, and show "copied to clipboard — press ⌘V" if nothing landed.

### Focused app and context reading
- App: `NSWorkspace.shared.frontmostApplication?.bundleIdentifier`. Window title: `kAXFocusedWindowAttribute` → `kAXTitleAttribute`. Browser URL: AppleScript to Safari/Chrome/Arc (VoiceInk `BrowserURLService.swift`) or the `AXURL`/`AXDocument` attributes.
- Focused element: `AXUIElementCreateSystemWide()` → `kAXFocusedUIElementAttribute` → `kAXRoleAttribute` / `kAXSubroleAttribute`. Text before the caret: `kAXSelectedTextRangeAttribute` + `kAXStringForRangeParameterizedAttribute` (or the slice of `kAXValueAttribute`). Selection: `kAXSelectedTextAttribute`.
- FluidVoice `DictationContextCapture.swift` (src) is the best reference:
  - Caps: `maxTextBeforeCursorCharacters = 2000`, `maxScreenLines = 300`, `maxVisitedElements = 4000`.
  - Sets `AXUIElementSetMessagingTimeout` so a hung app can't stall you.
  - Sets `AXManualAccessibility` on the app element to expose web content.
  - Skips password managers by bundle ID (1Password, Bitwarden, …) and secure text subroles.
  - Falls back to **Vision OCR of the window** (`recognizedWindowText`) when AX is empty, which is the Electron/canvas case. That needs the Screen Recording permission.
- Superwhisper's docs give the timing model: capture selected text at **recording start** (focus must still be on the app), and clipboard context when processing ([Superwhisper context docs](https://superwhisper.com/docs/common-issues/context), [Super mode](https://superwhisper.com/docs/modes/super)).
- **AX calls are synchronous IPC to the target app.** Run them off-main, with a 50–150 ms messaging timeout, and **in parallel with transcription** so they add zero latency.

## 1.4 Sandboxing & distribution

- **Why not the Mac App Store:**
  - Posting synthetic keyboard events (`CGEventPost`) and driving other apps' UI through AX are incompatible with App Review in practice. A clipboard manager was **rejected twice under Guideline 2.4.5 for `CGEvent.post` paste** ([Apple forum 820594](https://developer.apple.com/forums/thread/820594)).
  - DTS has said "Accessibility APIs are not supported in sandboxed apps" ([794253](https://developer.apple.com/forums/thread/794253)), while another DTS reply says sandboxed apps can request it ([756130](https://developer.apple.com/forums/thread/756130)). The contradiction itself is the risk.
  - AppleScript to System Events / browsers also needs temporary-exception entitlements under the sandbox.
  - Precedent: the MacWhisper MAS edition lacks system-wide dictation. VoiceInk, Superwhisper, Wispr Flow and FluidVoice all ship direct.
- **Ship:** Developer ID Application cert → **Hardened Runtime** (`--options runtime`) → `notarytool submit --wait` → `stapler staple` → DMG/ZIP plus Sparkle (EdDSA-signed appcast) and a Homebrew cask. Docs: [Hardened Runtime](https://developer.apple.com/documentation/security/hardened-runtime), [Notarizing macOS software](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution).
- **Entitlements (Hardened Runtime):**
  - `com.apple.security.device.audio-input` (required for the mic under the hardened runtime).
  - `com.apple.security.automation.apple-events` if you use AppleScript (browser URL, System Events paste).
  - `com.apple.security.cs.allow-jit` / `disable-library-validation` only if you embed runtimes or plugins that need them (avoid if possible).
  - The new Hex ships exactly `audio-input`, `automation.apple-events` and `personal-information.calendars` ([hex.entitlements](https://github.com/anomalyco/hex/blob/HEAD/.github/release/hex.entitlements)).
  - Info.plist: `NSMicrophoneUsageDescription`, `NSAppleEventsUsageDescription`. Accessibility and Input Monitoring have no Info.plist keys; they're TCC prompts via `AXIsProcessTrustedWithOptions([kAXTrustedCheckOptionPrompt: true])` and `CGRequestListenEventAccess()`/`IOHIDRequestAccess`.
- **TCC resets:**
  - TCC keys grants on the code-signing **designated requirement**, bundle ID and path.
  - **Ad-hoc signed builds have a cdhash-only DR**, so every rebuild loses Accessibility and Microphone. Sign dev builds with a stable Apple Development or Developer ID identity, keep the bundle ID and install path fixed, and use `tccutil reset Accessibility <bundle-id>` to clear stale rows ([Apple forum 721745](https://developer.apple.com/forums/thread/721745), [OpenClaw docs](https://docs.openclaw.ai/platforms/mac/permissions)).
  - Murmure's README documents users having to fully *remove* (not just untoggle) the app from Accessibility and Input Monitoring after an update that changed signing. Plan for a "permissions doctor" screen.
  - Also: after a grant, an existing event tap may need re-creation. Some apps require a relaunch (Murmure step 4).

## 1.5 Native stack options

| | Swift / AppKit (+SwiftUI) menubar | Tauri 2 (Rust + WebView) | Electron |
|---|---|---|---|
| Idle RAM (typical) | ~30–80 MB | ~60–150 MB (WKWebView process) | ~150–500 MB; Wispr Flow's Mac app is Electron (~526 MB bundle per [Desktop Insights](https://desktopinsights.com/apps/wispr-flow)) |
| Event tap / AX / NSPasteboard / AUHAL | First-class | Via `objc2` / `core-graphics` crates or a Swift sidecar (Handy uses `objc2-app-kit`, `rdev` fork, `handy-keys`, `enigo`) | Needs native Node addons or a Swift helper process (Wispr Flow reportedly runs a Swift helper owning the event tap, IPC to Electron, [teardown](https://wensenwucom-git-wensen-ora-real-agent-context-cveinnts-projects.vercel.app/thoughts/wispr-flow-investigation); OpenWhispr uses a Swift Globe-listener binary) |
| ML runtimes | CoreML/ANE via **FluidAudio** (Parakeet, Silero; Apache-2), **WhisperKit / argmax-oss-swift** (MIT), whisper.cpp, MLX-Swift, Apple `SpeechAnalyzer` (macOS 26) | whisper-rs, transcribe-rs/ONNX (Parakeet on CPU), transcribe-cpp + Metal, llama.cpp | Native addons or sidecar binaries |
| HUD overlay (non-activating panel) | `NSPanel` + `.nonactivatingPanel` (never steals focus, which is critical) | `tauri-nspanel` (Handy) | Hard; BrowserWindow focus quirks |
| Cross-platform | No | Yes | Yes |
| Latency budget impact | Minimal; everything in-process | Small; the IPC to the webview is off the hot path | Extra hops if the helper ↔ renderer IPC is in the hot path |

**Verdict for macOS-only, latency-first:** Swift.
- AppKit for the event tap thread, the `NSPanel` HUD, AX and the pasteboard.
- SwiftUI for settings.
- FluidAudio for Parakeet TDT v2/v3 on the ANE (FluidVoice and VoiceInk both use it; FluidVoice claims "pretty much zero delay").
- An optional in-process llama.cpp/MLX for cleanup.

Rust/Tauri is the right call only if Windows/Linux matter later.

## 2.1 Fork-base assessment (macOS-only, latency-first)

| Candidate | Fit | Pros | Cons |
|---|---|---|---|
| **FluidVoice** | ★★★★★ if GPL is OK | Native Swift; fastest Parakeet/Nemotron streaming; already has **Command Mode + Write Mode + context capture**; very active; free | GPL-3 (fork must stay GPL); large codebase (meeting features, Windows port); the "Fluid Intelligence" LLM is closed |
| **VoiceInk** | ★★★★ if GPL is OK | Best-tested paste/hotkey/audio layers; modes per app/URL; auto-learn dictionary | GPL-3; maintainer doesn't accept PRs (forks drift); paid-app licensing code to strip; no voice-command layer |
| **Hex legacy (Swift/TCA)** | ★★★★ for MIT | MIT; small; pure, unit-tested hotkey state machine; FluidAudio/WhisperKit already wired | Archived; TCA learning curve; thin LLM/context features (you'd build them, which is the differentiator anyway) |
| **OpenSuperWhisper** | ★★★ | MIT Swift; single-modifier and mouse triggers; Homebrew | Fewer robustness fixes; no LLM/context |
| **Handy** | ★★★ (macOS-only) | MIT, huge community, superb edge-case handling | Tauri/webview and cross-platform abstractions add weight; feature freeze; you'd fight it to go macOS-native |
| OpenWhispr (for comparison) | ★★ | MIT, has a Globe listener and BYOK | Electron + Swift helper sidecar = the architecture we're trying to beat on latency and memory |

**Recommendation:**
- **If MIT/permissive matters** (commercial or closed later): start a fresh Swift app or the **legacy Hex** codebase. Port *ideas* (not code) from the GPL apps: VoiceInk's tap thread and paste sessions, FluidVoice's context capture. Copy MIT code freely from Handy, translating its Secure Input fallback and promise pasteboard to Swift, and from OpenWhispr's Globe `TISUpdateFnUsageType` handling.
- **If GPL-3 is acceptable:** **fork FluidVoice**. It already ships most of what a Wispr Flow replacement needs (dictation + command + rewrite + context), and it's Swift-native and fast.

## 2.3 Known-issue lessons from trackers (to design for up front)

- Chromium web fields: synthetic ⌘V fails intermittently, AX menu paste works ([VoiceInk #1000](https://github.com/Beingpax/VoiceInk/issues/1000)).
- Clipboard loss on back-to-back dictations ([VoiceInk #1024](https://github.com/Beingpax/VoiceInk/issues/1024)).
- Held modifiers leak into the synthesized paste chord ([Handy #2051](https://github.com/cjpais/Handy/issues/2051)).
- Bare-Fn binding swallowing Fn chords ([Handy #1767](https://github.com/cjpais/Handy/pull/1767)).
- Bluetooth: media pause, silent first buffers, HFP downgrade ([Handy #1146](https://github.com/cjpais/Handy/pull/1146), [#2154](https://github.com/cjpais/Handy/pull/2154), [#1991](https://github.com/cjpais/Handy/pull/1991)).
- Stale AUHAL after sample-rate change → empty recordings ([VoiceInk #956](https://github.com/Beingpax/VoiceInk/issues/956)).
- Terminal and embedded-webview insertion failures ([FluidVoice #479](https://github.com/altic-dev/FluidVoice/issues/479), [#1184](https://github.com/altic-dev/FluidVoice/issues/1184), [#1013](https://github.com/altic-dev/FluidVoice/issues/1013)).
- Electron apps hide edits from AX ([VoiceInk #977](https://github.com/Beingpax/VoiceInk/issues/977)).
- Post-processing: a new HTTPS connection per dictation costs ~1 s, so **keep the LLM client connection warm** ([Handy #2333](https://github.com/cjpais/Handy/issues/2333)).
- Leaked Secure Input from other apps disables all taps ([Cursor forum](https://forum.cursor.com/t/cursor-leaks-secure-event-input-breaks-all-system-wide-input-taps-until-quit-or-screen-lock/167585)).
